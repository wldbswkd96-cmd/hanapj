# hanapj — WLF 자동 스크리닝

준법지원부 AML 담당자가 계약체결 품의서를 받을 때마다 계약업체명·대표자명을 수기로 WLF(요주의 인물/법인 리스트)에 검색하던 업무를 자동화하는 프로토타입입니다.

- 배포(아티팩트): https://claude.ai/artifact/9piCqP5CaCSRWhbbfEk7LA
- 소스: [`wlf-screening/index.html`](wlf-screening/index.html) (화면), [`api/extract.js`](api/extract.js) (Vercel 서버리스 함수)

## 배포 경로 두 가지

| | 아티팩트 (claude.ai) | Vercel |
| --- | --- | --- |
| AI 추출 | 보는 사람의 Claude 계정 (`claude.use("sample")`) | `/api/extract` → Anthropic API (`ANTHROPIC_API_KEY`) |
| 판정·등록 품의서 저장 | 팀 공유 저장소 (실시간 반영) | 이 브라우저(localStorage) |
| AI를 못 쓸 때 | 규칙 기반 추출로 자동 전환 | 규칙 기반 추출로 자동 전환 |

### Vercel 설정

- 빌드: `vercel.json`이 `npm run build`로 `wlf-screening/index.html`에 문서 골격을 씌워 `dist/index.html`을 만들고, `dist`를 정적 출력으로 씁니다. 별도 프레임워크 설정은 필요 없습니다(Framework Preset: Other).
- 환경 변수
  - `ANTHROPIC_API_KEY` (필수): 없으면 화면은 규칙 기반 추출로만 동작합니다.
  - `WLF_ACCESS_KEY` (권장): 설정하면 `x-wlf-key` 헤더가 일치하는 요청만 AI 추출을 호출할 수 있습니다. 공개 URL에서 API 비용이 무단으로 쓰이는 것을 막습니다. 화면 상단의 AI 상태 칩을 눌러 키를 입력합니다.
- 모델: `claude-opus-5-5`, 구조화 출력(JSON 스키마)으로 응답을 받고, 안전 분류기 거절 시 서버 측 대체 모델로 재시도(`fallbacks: "default"`)합니다.

## 완료조건 대응

| 완료조건 | 구현 |
| --- | --- |
| AI가 계약업체명·대표자명 자동 추출 (정확도 95% 이상) | Claude가 품의서에서 업체명·대표자명(공동대표 포함)·근거 문장을 JSON으로 추출. "추출 정확도 검증" 탭에서 합성 품의서 24건(필드 48개)으로 정확도를 실측하고 95% 목표선과 비교. AI를 쓸 수 없으면 규칙 기반 추출기로 대체 |
| 수기 입력 없이 WLF 자동 조회 | 추출값을 바로 WL 명단과 매칭. 법인격 표기·공백 정규화 후 한글 자모 단위 편집거리로 유사도를 계산해 오타·띄어쓰기·별칭까지 탐지 |
| WL 매칭 위험건 즉시 알림 | 유사도 0.95 이상은 WL 일치, 0.80 이상은 유사·검토로 분류해 토스트·알림함에 즉시 표시. 다른 담당자가 등록한 품의서도 공유 저장소로 실시간 수신 |
| 불일치·검색누락 0건 관리 | 추출값이 원문에 글자 그대로 있는지 대조하고, AI와 규칙 추출 결과를 교차검증. 불일치·누락 건수를 KPI로 표시하고, 원문과 맞지 않으면 '이상 없음'으로 닫을 수 없도록 차단. 담당자 판정은 검토 이력에 남음 |

## 품의서 등록 (PDF 업로드)

'+ 품의서 등록'에서 **PDF를 끌어다 놓거나 선택**하는 것이 기본 방식입니다. 제목·기안부서·본문은 선택 입력입니다.

- 글자가 있는 PDF는 브라우저에서 본문을 읽고(pdf.js), 문서번호·제목·기안부서를 본문에서 자동으로 채웁니다. 선택 입력에 값을 넣으면 그 값이 우선합니다.
- 글자가 없는 스캔본은 앞 5쪽을 이미지로 바꿔 Claude가 본문을 옮겨 적고 업체명·대표자명을 함께 추출합니다. 아티팩트에서는 보는 사람의 Claude, Vercel에서는 `/api/extract`(이미지 모드)를 씁니다.
- PDF 없이 본문만 붙여 넣어도 등록됩니다. PDF와 본문을 함께 넣으면 본문은 추가 메모로 덧붙습니다. .txt 파일도 받습니다.

### 첨부가 있는 품의서 (압축파일·여러 파일)

품의서에는 보통 계약업체명만 있고 대표자는 첨부 서류(사업자등록증, 법인 등기사항증명서 등)에 있습니다. 그래서 **.zip 압축파일**이나 **여러 파일을 한꺼번에** 올릴 수 있습니다.

- 읽는 형식: PDF(글자·스캔본), .docx, .hwpx, .txt, .jpg/.png(Claude가 판독). 한글 **.hwp는 읽지 못하므로** PDF나 .hwpx로 저장해 올려야 합니다. 압축 안의 압축은 풀지 않습니다.
- Windows에서 만든 압축파일의 한글 파일명(CP949)도 깨지지 않게 읽습니다.
- 파일명에 '품의'가 들어간 파일을 품의서로 고르고, 목록에서 다른 파일을 품의서로 바꿀 수 있습니다.
- 품의서 본문 뒤에 첨부를 `════ [첨부 n] 파일명 ════` 구분선과 함께 이어 붙여 추출·원문 대조·하이라이트에 씁니다.
- 대표자명을 첨부에서 가져온 경우, **그 첨부에 계약업체명도 있어야** 통과합니다. 다른 회사 서류(예: 견적서의 공급자)에서 대표자를 잘못 집으면 '자동 조회 보류'로 막고 담당자 확인을 요구합니다.

## WL 명단 갱신 (엑셀 업로드)

'WL 명단' 탭의 **엑셀 업로드** 버튼으로 최신 명단 파일(.xlsx, .xls, .csv)을 올리면 전체 명단을 교체합니다.

- 첫 시트를 읽고, 첫 10행 안에서 머리글을 찾습니다. **등재명** 열(이름·성명·상호도 인식)은 필수이고, WL ID·구분·별칭·리스트·등재 사유 열은 있으면 읽습니다.
- 별칭은 쉼표로 구분합니다. 구분이 비어 있으면 이름으로 법인/개인을 추정합니다. WL ID가 없으면 자동으로 매기고, 중복 ID와 등재명이 빈 행은 제외하고 알려 줍니다.
- 적용 전에 추가·변경·삭제 건수를 미리보기로 보여 줍니다. 적용하면 수신함의 모든 품의서를 바로 다시 조회하고, 새로 걸린 건은 알림으로 띄웁니다.
- CSV는 UTF-8과 CP949(EUC-KR, 엑셀 기본 저장) 모두 읽습니다.
- **양식 받기**는 현재 명단을 같은 머리글의 .xlsx로 내려받습니다. 내려받아 고친 뒤 다시 올리면 됩니다.
- 저장 위치: 아티팩트에서는 팀 공유 저장소(모든 담당자 화면에 실시간 반영), Vercel에서는 이 브라우저(localStorage)입니다.

## WLF 도우미 (챗봇)

화면 오른쪽 아래 **도우미** 버튼으로 엽니다. 지금 보고 있는 품의서의 추출값·WLF 조회 결과·담당자 판정·본문 앞부분을 함께 보내(체크박스로 끌 수 있음) 판정 근거, 추가 확인할 점, 처리 절차를 묻고 답합니다.

- Vercel: `/api/chat` → OpenRouter. 환경 변수 `OPENROUTER_API_KEY`(필수), `OPENROUTER_MODEL`(선택, 기본 `nvidia/nemotron-3.5-lightning:free`). 다른 무료 Nemotron 예: `nvidia/nemotron-3-super-120b-a12b:free`, `nvidia/nemotron-3-ultra-550b-a55b:free`. `WLF_ACCESS_KEY`를 설정하면 이 엔드포인트도 같은 키로 보호됩니다.
- 아티팩트: 보는 사람의 Claude로 답합니다.
- **주의:** OpenRouter의 무료 모델은 제공사가 입력을 기록·학습에 쓸 수 있습니다. 실제 고객·거래 정보를 보낼 계획이면 유료 모델이나 데이터 보존이 없는 제공사로 바꾸세요(OpenRouter 설정의 데이터 정책 참고).

## 참고

- 예시 품의서·업체·인물과 WL 명단은 모두 **테스트용 가상 데이터**입니다.
- 운영 연동 시 `WL` 상수와 `screenName()`을 AML 시스템 WLF 임의수행 조회 API 호출로 바꾸고, 포털 수신 이벤트를 `inbox` 컬렉션 등록으로 연결하면 됩니다.
